# Issue Tracker

## Provider

**None.** This is a self-contained hackathon submission; there is no external
tracker (GitHub Issues, Linear, Jira, …) attached to it.

## Where work is tracked instead

- **Roadmap / next steps:** `README.md` → "Known limitations & next steps"
- **Decisions:** `.ai/decisions/` (ADR format) and `docs/ARCHITECTURE.md`
- **Remaining work:** `docs/agents/HANDOFF.md`
- **Submission checklist:** `README.md` → "Submission deliverables" table

## If a tracker is adopted later

Use this structure per issue: Summary · Business value · Context · Scope ·
Non-goals · Acceptance criteria · Technical notes · Testing requirements ·
Dependencies. Do not invent labels before the team defines them.
